# Architecture Decisions

## ADR-001 Hybrid detection
Use rules/ML for detection and prioritization; use the LLM for synthesis, explanation and investigation guidance.

## ADR-002 Synthetic-first
Start with deterministic synthetic data to make training/evaluation reproducible.

## ADR-003 Local Qwen 3 8B
Use the local model first. Discover/verify its exact runtime tag instead of hardcoding it.

## ADR-004 Attributable RAG
Every retrieved chunk keeps source metadata and final answers cite source IDs.

## ADR-005 Explicit uncertainty
Anomaly, suspicion, possible attack and confirmed malicious activity must remain distinct.

## ADR-006 Modular typed dataset validation and single source of truth
Define dataset schema, column types, bounds, and manifest constraints in `src.data_validation.schema` as the single programmatic source of truth aligned with `docs/DATASET_SPEC.md`. The validation subsystem returns typed result objects (`ValidationCheckResult`, `ValidationReport`) with explicit `PASS`/`FAIL` states, diagnostic metadata, and user-facing reports without leaking stack traces or mutating canonical seeded datasets.

## ADR-007 Baseline Isolation Forest anomaly detection & leakage prevention
Use `sklearn.ensemble.IsolationForest` fitted exclusively on normal-only training data using 17 numeric behavioral features. Exclude identifiers (`window_id`), target labels (`label`), and anomaly metadata (`anomaly_type`) to eliminate data leakage. Omit categorical columns (`user_role`, `host_type`) from the baseline to prevent arbitrary ordinal encoding. Derive operational anomaly decision thresholds deterministically from the 95th percentile of the training normal score distribution to calibrate an expected 5% baseline false positive rate without peeking at evaluation anomaly labels.

## ADR-008 Explainable risk scoring architecture and critical safeguard
Implement transparent, bounded priority risk scoring ($0.0 \le \text{risk\_score} \le 100.0$) combining Phase 2 Isolation Forest anomaly signals ($40\%$ max weight) and training-normal derived behavioral indicators ($60\%$ max weight). Derive behavioral baseline thresholds deterministically from the 99th percentile of normal-only training data without peeking at evaluation labels. Guarantee full mathematical breakdown reconciliation where the sum of components matches the reported score within a $0.01$ tolerance. Enforce an operational critical-alert safeguard requiring corroborating behavioral evidence before escalating any alert to CRITICAL severity, and treat missing telemetry fields as unobserved with zero contribution rather than fabricating negative baseline facts.

## ADR-009 Authoritative MITRE ATT&CK Enterprise catalog ingestion and deterministic behavior mapping
Ingest official STIX 2.1 Enterprise ATT&CK objects (`enterprise-attack` domain, v14.1) directly from verified distributions with bundle validation, SHA-256 integrity checks, and local artifact caching to prevent repeated remote downloads. Separate technique lookup services (`lookup_attack_technique`, adhering to the tool contract in `docs/TOOL_CONTRACTS.md`) from behavior-to-technique mapping. Implement deterministic, typed behavioral mapping rules (`BehaviorMappingRule`) that evaluate only observable telemetry evidence without peeking at synthetic ground-truth labels (`anomaly_type`, `label`) or using an LLM. Candidate techniques must exist in the verified catalog, and unsupported or low-evidence alerts must return explicit `INSUFFICIENT_EVIDENCE` or `NOT_MAPPED` statuses. Alert integration (`AlertWithMitreContext`) enriches alerts with adversary context while strictly preserving original Phase 2 anomaly scores, Phase 3 risk scores, and evidence breakdowns.

## ADR-010 Structure-aware RAG pipeline, hybrid retrieval, and multi-stage relevance verification
Ingest approved cybersecurity knowledge sources (MITRE ATT&CK STIX, YAML Sigma rules, Markdown guides) recorded in a typed source manifest (`data/knowledge_base/sources_manifest.json`) with cryptographic SHA-256 integrity validation. Reject fixed-character window chunking in favor of structure-aware extraction preserving ATT&CK technique headers, atomic Sigma detection logic, and Markdown heading hierarchies (`heading_path`) with deterministic, content-hash-backed chunk IDs (`generate_stable_chunk_id`). Use a local-first embedding strategy discovering the Ollama `embeddinggemma:latest` model (768-d) at runtime without silent cloud fallbacks, paired with a persistent ChromaDB / SQLite vector store and a persistent Okapi BM25 lexical index. Implement hybrid retrieval combining dense semantic similarity and lexical scores via Reciprocal Rank Fusion ($k=60$) with exact identifier boosting (ATT&CK technique IDs and Windows Event IDs). Enforce a multi-stage relevance verification gate requiring exact identifier matching, dual dense/lexical agreement ($\ge 0.52$ dense, $\ge 6.0$ lexical), or high single-channel confidence ($\ge 0.60$ dense, $\ge 9.0$ lexical) to return `NO_RESULTS` on out-of-scope queries rather than hallucinating irrelevant nearest neighbors.
## ADR-011 Local Qwen 3 8B Security Investigation Engine and Deterministic Evidence Attribution
Integrate a local instance of `qwen3:8b` via Ollama as the investigation and explanation layer rather than the primary detector. Discover installed model tags at runtime via `/api/tags` and raise explicit `ProviderUnavailableError` or `ModelNotFoundError` without falling back to cloud models. Pass structured, validated telemetry and upstream outputs (`InvestigationInput`) synthesizing Phase 2 ML anomaly predictions, Phase 3 explainable risk scores, Phase 4 MITRE ATT&CK behaviors, and Phase 5 hybrid RAG chunks. Enforce application-state preservation where the LLM cannot mutate application-owned alert identifiers, severity levels, or risk scores. Validate structured JSON reports through a deterministic validation gate (`ReportValidator`) that verifies citations against actual retrieved RAG chunk IDs, filters unverified ATT&CK technique identifiers, and maps model outputs into structured investigation findings (`FindingType`).

## ADR-012 Bounded LangGraph Investigation Workflow and Local Tool Orchestration
Evolve the Phase 6 single-shot investigation pattern into a bounded, deterministic state graph using LangGraph (`StateGraph`). The agent manages evidence collection over strictly verified, read-only application tools (`search_logs`, `get_related_events`, `search_knowledge_base`, `lookup_attack_technique`) to enrich incoming Phase 3 `SecurityAlert`s. Synthetic 1-hour behavioral windows are explicitly tagged as `aggregated_behavioral_window` to ensure cybersecurity truthfulness rather than fabricating raw EVTX logs or Sysmon event sequences. Strict runtime limits prevent unbounded execution through configurable caps on iterations (`max_iterations=4`), tool invocations (`max_tool_calls=4`), LLM queries (`max_llm_calls=3`), and total investigation wall-clock duration (`total_deadline_seconds=300.0`). The agent guarantees application-state preservation: original alert identifiers, ML anomaly scores, risk scores, and severity ratings remain strictly immutable throughout graph execution. An in-memory LangGraph checkpointer (`MemorySaver`) maintains deterministic state persistence across thread executions without external distributed infrastructure.

## ADR-013 Backend API Architecture, Local Binding, and Concurrency Bounding
Expose security detection, explainable risk scoring, MITRE ATT&CK behavior mapping, hybrid RAG knowledge retrieval, and LangGraph multi-step investigations via a local-first FastAPI backend service. Enforce loopback-only network interface binding (`127.0.0.1`) by default to prevent unintentional network exposure of sensitive organizational telemetry without authenticated perimeter gateways. Implement request tracing middleware that attaches and propagates correlation identifiers (`X-Correlation-ID`) across incoming requests and investigation traces. Sanitize client-facing error payloads (`ErrorResponse`) to prevent leaking internal stack traces, local filesystem paths, or model provider diagnostics. Guard long-running LLM investigation endpoints with a bounded concurrency semaphore (`asyncio.Semaphore(1)`) to serialize model execution on local hardware, preventing GPU VRAM thrashing and model deallocations without requiring distributed queue infrastructure.

## ADR-014 Local-First SOC Dashboard Architecture and Traceable Evidence Presentation
Build the security operations frontend as a responsive, typed single-page application using React 19, TypeScript, and Vite, paired with a cybersecurity SOC dark theme design system. Route all data interactions through a centralized, typed API client (`ApiService`) configured via `VITE_API_BASE_URL` with structured error handling, network failure recovery, and correlation ID preservation. Enforce cybersecurity truthfulness across all views: prominently label data as synthetic aggregated behavioral windows, distinguish statistical anomalies from confirmed security compromises, preserve immutable Phase 3 risk scores without client recalculations, and render validated Phase 7 LangGraph investigation reports with collapsible, source-attributed RAG citations. Prevent duplicate LLM investigation requests during local inference execution using client-side disabled state guards and live elapsed timers.

## ADR-015 Artifact-First Evaluation Architecture and Layered Quality Gates
Implement Phase 10 evaluation as a multi-layer framework that distinguishes between (a) re-running heavy pipelines and (b) reading existing computed artifacts. Sub-evaluations for ML (Phase 2 `metrics.json`) and RAG (Phase 5 `retrieval_eval_report.json`) read previously computed artifacts rather than re-executing slow inference pipelines to avoid duplicating ~30s+ computation runs on constrained hardware. Sub-evaluations for structured output validation and agent contract testing run deterministically without the Ollama model, enabling CI-safe execution. API endpoint evaluation is opt-in via `--api` flag because it requires a live backend process. Record `BLOCKED` (not `FAIL`) when a required service or artifact is unavailable, to distinguish infrastructure gaps from software defects. Define numeric quality gates (F1 ≥ 0.80, FPR ≤ 0.15, Recall@5 ≥ 0.80, rejection rate ≥ 0.90) that reflect minimally acceptable performance on synthetic benchmarks without fabricating real-world guarantees. Assemble all sub-results into a consolidated `evaluation_summary.json` and human-readable `EVALUATION_REPORT.md` via a dedicated `assemble_evaluation_report.py` assembler, making the report reproducible and diffable across runs.
